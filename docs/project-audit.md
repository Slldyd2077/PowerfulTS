# 项目优化审查（2026-10-03）

基于 0.12.8 的代码进行 0.13.1 适配和发布改造。此文档记录真实发现及验证边界，不把离线测试当作生产或音频端到端证据。

## 本次修复

| 发现 | 影响 | 改进 |
| --- | --- | --- |
| Origin 固定取默认 TSMUSIC_URL | per-user / per-bot 指向其他引擎时写请求 CSRF 403 | 按客户端地址生成 Origin |
| 上游登录只初始化一次 | 引擎重启 / cookie 过期后音乐和通话中断 | 单次 401 重新认证及并发登录锁，不对网络超时重放写请求 |
| 平台音乐 / 登录 API 未始终带默认 botId | fork 的 per-bot provider 选择失败 | 显式 ID 优先，回退配置默认 ID |
| 混合平台歌单用统一 platform | 入队后选错音源，业务失败仍算成功 | 按曲目音源传参，检查上游业务失败 |
| 平台登录省略 botId 后回退默认引擎实例 | 未经过当前账号所有权校验 | 登录 / cookie / Jellyfin 操作要求显式且属于当前账号的 botId |
| Docker Python 依赖为无上限范围 | 不同时期重建产物不同 | 导出 uv 锁及哈希，Docker require-hashes 安装 |
| Axios / AnyIO 有已知安全公告 | 依赖风险 | 最小升级并重新扫描 |
| Linux 未映射宿主机地址 | 复制文档地址后连接不上 | Compose 增加 host-gateway |
| 前后端启动顺序不保证就绪 | 首次访问短暂 502 | 健康检查及 service_healthy 依赖 |
| nginx 静态扩展名规则覆盖 API | 图片等 API 错误 404 | `/api/` 使用 `^~` 优先代理 |
| 无正式发布包或流水线 | 用户需下载源码并自己构建 | 双 CPU 预构建安装包、启动停止脚本、校验和与 tag 发布 |
| Windows PowerShell 的原生 stderr 探测会抛错 | 干净安装没有镜像时在导入前退出 | 探测局部捕获退出码，镜像缺失后正常导入 |
| 轮询重叠且后台持续请求 | 慢请求堆积、隐藏页面仍消耗服务资源 | 串行轮询，隐藏 / 离线暂停，恢复刷新 |
| 小图标使用 1.4 MB PNG 和外部字体 | 内网 / 国内网络首屏资源浪费 | 导航 / favicon 使用已有 SVG，采用本地字体回退 |

## 后续值得优化

1. **覆盖率和真实链路验证**：现有后端全量覆盖率约 50%，低于 ECC 的 80% 目标，管理设置、Steam、TSQuery 等仍有空白。新增发布脚本和前端调度器应分别达到 80%；需要继续补核心授权和第三方接口集成测试，以及真实 TS3 麦克风上下行、入场音效和平台账号登录验收。
2. **管理设置重启语义**：管理端设置保存到数据库，启动客户端仍主要取环境配置，需要专门核对各项热重载和重启后的持久化行为，避免页面显示已配置而运行客户端使用旧值。
3. **前端体积**：Element Plus 全量注册及全量图标引入，使入口压缩前约 850 KB。值得采用按需组件 / 图标引入，但需要覆盖所有视图，不能只拆 chunk 或提高 warning 阈值来宣称首屏变快。
4. **认证与隐私**：localStorage token 在 XSS 场景下可读；后续可设计 HttpOnly cookie 与 CSRF 配套迁移。首个注册者成为管理员是既有行为，因此新安装默认只绑定本机并要求管理员先注册。公开监控 / 游客浏览是既有功能，应给服务器管理员更清晰的访问控制选项。
5. **TSMusicBot 升级路线**：原版上游已有 1.14.0 更新记录，和专用 fork 的 per-bot API 不同。后续升级需要把网页语音、音效可信 origin、语音闪避与多实例补丁移植到新基线，再做契约测试和真实音频验证；不能仅改 README 的版本号或换 latest 镜像。
6. **跨平台边界**：Docker 包运行 Linux 容器，支持 amd64 / arm64；不包含无需 Docker 的原生 EXE / App / systemd 安装器，32 位 NAS 不在发布矩阵。

测试通过只说明被测试的契约；发行构建、各架构安装烟测与真实服务验收分别记录，失败应保留明确状态。

## 本地验证

- 后端 197 个测试及 6 个子测试通过；6 个平台登录接口分别验证缺少 botId、非拥有者、拥有者三种场景。
- 前端 25 个 Node 测试通过；新增调度器行覆盖率 100%、分支 97.67%。
- 发布脚本行覆盖率 87%；Windows 打包 / 启动器 11 项通过、2 项 POSIX 测试按平台跳过；POSIX 项另在 Linux 容器验证。
- Python 锁依赖及前端全部依赖安全扫描未报告已知漏洞。这不等于应用不存在安全问题。
- amd64 Docker 前后端严格构建通过。安装包在 Windows Docker Desktop 解压启动、健康检查、重启、停止和数据保留均通过。
- Edge 无头浏览器桌面 / 移动端登录页及游客面板通过，未见页面 JS 错误；未启动真实 TS3 / TSMusicBot 音频或平台账号登录验证。
- ARM64 镜像及 macOS / Windows 启动器的 GitHub Actions 发布检查为独立证据，以对应 tag 的实际运行结果为准。
