# PowerfulTS 宣传视频脚本 V2｜B 站科技区口播版

## 视频定位

- 推荐标题：**都 2026 年了，为什么还有人死守 TeamSpeak？我顺手给它搓了个 Web 面板**
- 备选标题：**嫌 KOOK 太花，嫌 TS 太素？给技术宅做的 TeamSpeak 控制台｜PowerfulTS**
- 建议时长：约 5 分 35 秒（科技区常见的偏利落口播语速）；若需要短视频投放版，再单独压成 90 秒
- 画幅：16:9，3840×2160 或 1920×1080，30fps
- 形式：第一人称口播 / 配音 + 实机录屏 + 少量解释动效
- 画面占比：实机与代码约 60%，口播或虚拟形象约 25%，动效与梗图约 15%
- 受众：会自建服务器、用 VPS / NAS / Docker、愿意折腾 Bot 和插件的 TeamSpeak 用户
- 语感：像作者在给同好展示自己刚搓出来的东西，而不是企业在开产品发布会

## 开场基调

不要使用宏大 Logo 动画开场。第一秒直接进人话，字幕全程保留。普通字幕为白色，关键词偶尔使用 PowerfulTS 品牌蓝；梗只在确实好笑的位置停半秒，不要每句话都抖字、放表情包。

### 场景 1 - INT. 口播桌面 / 电脑房 - 夜晚（0:00–0:18）

**旁白**

**字幕重点**

`为了少 20ms，权限能配一晚上`

**剪辑 / 音效**

第一句直接干声开场。每个特征用硬切和轻微点击音，不放史诗 BGM。权限列表滚动到看不见底时，画面停顿 6 帧，右下角出现小字：`这很 TeamSpeak`。

## 第二章：TeamSpeak 很纯粹，也纯粹过头了（1:00–2:06）

### 场景 4 - INT. TeamSpeak 客户端 / 延迟测试 - 同时（1:00–1:24）

**旁白**

> TeamSpeak 走的是另一条路。核心客户端免费，没有广告，也不需要买个会员才能正常说话；服务端还能自己搭。数据放在哪、权限怎么给、要不要只在内网跑，都是服主自己决定。

**字幕重点**

`低延迟 / 自建 / 权限 / 控制权`

底部事实注释：`TS3 非商业自建原生许可：1 个虚拟服务器 / 32 槽免费；更大规模需另行授权`

**剪辑 / 音效**

这一段不做炫技，录屏保持干净。延迟数字使用局部放大，连接成功时保留 TeamSpeak 实际提示音。

### 场景 8 - INT. 架构图与代码 - 稍后（2:21–2:39）

**旁白**

> 整体架构也没什么黑魔法。前端是 Vue 3，后端是 FastAPI。监控、登录验证和好友数据，通过 TS3 ServerQuery 加 SQLite 处理；浏览器只需要访问 PowerfulTS 这一套接口。
>
> 说人话就是：TS 继续负责语音，PowerfulTS 负责把那些散落在终端和脚本里的东西，收进一个网页。

**画面**

架构图按旁白逐层出现：`Vue 3 → FastAPI → TS3 ServerQuery / SQLite`。切三组真实文件：`monitor.py`、`ts3_query.py`、前端 Dashboard 组件。

**剪辑 / 视觉效果**

架构线条随解释出现，不提前把整张图堆满。代码只高亮文件与关键函数，不滚“黑客代码雨”。

**画面**

先完整显示 TSMusicBot 项目名称、作者仓库和 MIT License，再进入 PowerfulTS 音乐中心。依次实操搜索、播放、队列拖动、切换音质、收藏到 TS 歌单。

**署名字幕**

`音乐与点播引擎：ZHANGTIANYAO1 / TSMusicBot`

`github.com/ZHANGTIANYAO1/teamspeak-music-bot`

**剪辑 / 音效**

Credits 至少完整停留 3 秒。操作画面跟随鼠标原速或 1.2 倍速，不把十个功能压进两秒钟蒙太奇。

> 于是就有了 PowerfulTS。简单来说，它是一个给 TeamSpeak 服务器用的 Web 面板，目前版本是 0.11.0。先打个预防针：这是早期测试版，不是什么“重新定义语音”的商业项目，Bug 肯定还有，而且大概率不少。
>
> 整体架构也没什么黑魔法。前端是 Vue 3，后端是 FastAPI。监控、登录验证和好友数据，通过 TS3 ServerQuery 加 SQLite 处理；浏览器只需要访问 PowerfulTS 这一套接口。说人话就是：TS 继续负责语音，PowerfulTS 负责把那些散落在终端和脚本里的东西，收进一个网页。
>
> 首页先解决最基础的问题：服务器在线没有、现在有多少人、分别在哪个频道、上线多久、在玩什么游戏。频道树和游戏人数都会显示，默认每五秒刷新一次。以前这些信息不是看不见，只是得去 Query 里自己捞。现在至少像个正常网页了。
>
> 然后是大部分人最容易问到的音乐。这里 Credits 先说在前面：PowerfulTS 没有从零再造一个音频机器人。音乐搜索、播放控制和 B 站点播，核心引擎来自开源项目 TSMusicBot。PowerfulTS 做的是把它接进自己的账号、好友和权限体系。现在可以统一搜索网易云、QQ、酷狗和 B 站，控制播放、队列、音质和播放模式；还能建一套独立于平台的 TS 歌单，把不同来源的歌混在一起收藏。
>
> Bot 也可以有多个，分别放在不同服务器或者频道。队列支持长按拖动，Bot 能在好友之间共享；如果你懒得找歌，甚至可以主动授权浏览器，把某个应用的声音实时送进当前音乐机器人。当然，整屏共享很容易把 TS 自己的声音再录进去，喜提回声地狱，所以最好只选单独的应用窗口。
>
> 登录这块没有再发明一套陌生身份。注册时绑定 TS 昵称，验证码直接通过 TeamSpeak 私聊发给本人。登录之后可以加好友、看在线状态，还能给不同好友单独开上线提醒。默认走 TS 私聊；如果你平时不一直挂着客户端，也可以选配 NapCat，通过 OneBot 把提醒发到 QQ。
>
> 最近还接了 Steam OpenID。绑定之后能看自己和好友的在线状态、共同游戏和游戏时长排行，TS 监控里也会直接显示好友现在玩的 Steam 游戏。这个功能没有什么伟大意义，主要是解决“今晚到底玩什么”这个人类长期难题。
>
> 另外还有管理后台、通知模板、NapCat 连通性检测和完整的移动端适配。部署方面提供 Docker Compose，Linux、Windows、macOS 和 NAS 都能跑。
>
> PowerfulTS 现在以 MIT License 开源，代码就在 GitHub。这个项目目前更像是我把自己服务器上的需求一项项做出来，再慢慢整理成别人也能部署的版本。所以如果你期待的是装完以后百分之百稳定、所有环境一次点亮，那我建议先等一等；但如果你本来就喜欢 TeamSpeak，也愿意折腾 Docker、看日志、提 Issue，那你大概率就是这个项目现在最需要的用户。
>
> 如果你发现 Bug、觉得文档哪儿没说人话，或者正好也想给 TS 加个奇怪功能，都可以开 Issue 或者直接提 PR。哪怕只是补一段部署说明，也比在评论区留一句“怎么不能用”更容易解决问题。
>
> TeamSpeak 不一定需要变成另一个 Discord。它可能只是缺一个更适合这群技术宅的现代化控制台。PowerfulTS 目前做的，就是这件事。

## 剪辑语言约束

- 以硬切、J-cut、L-cut、局部放大和鼠标圈选为主，不使用发布会式全屏关键词轮播。
- 旁白说到哪个功能，画面就真实操作哪个功能；不要让画面提前剧透下一段。
- 梗来自 NAS、VPS、权限组、周末项目、回声和日志等真实技术经历，不硬塞流行语。
- 口播画面允许保留轻微停顿和呼吸，不把每个空隙都塞满音效。
- 功能页面必须使用可公开的演示数据，避免展示真实 TS 地址、Steam 身份、QQ 号、Token 和 ServerQuery 凭据。
- 竞品比较引用官方页面，只讨论产品方向和公开会员权益；不伪造卡顿、广告或崩溃画面。
- TSMusicBot 署名在第一次介绍音乐时完整出现；NapCat 明确标注为可选依赖。

## 参考视频中借鉴的高层方法

- 用具体生活场景开启技术问题，不先念产品定位。
- 主持人 / 讲解者是叙事主体，官网和实机画面负责提供证据。
- 先解释“为什么有人需要它”，再进入安装或功能。
- 技术术语不回避，但会马上补一句“说人话就是”。
- 字幕、局部放大和鼠标指示承担大部分信息提示，转场保持克制。

以上只借鉴科技区教程常见的叙事方法与节奏，不复刻参考作者的固定口头禅、逐句表达或视觉包装。
