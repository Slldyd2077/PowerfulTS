# PowerfulTS 开源项目宣传片脚本 V1

## 成片定位

- 片名：**《低延迟，不该等于低体验》**
- 建议时长：约 140 秒（正常偏利落的中文旁白语速）
- 画幅：16:9，1920×1080，30fps
- 受众：TeamSpeak 服主、游戏公会、固定开黑队、开源开发者
- 语气：前段克制吐槽，中段快速展示，结尾真诚邀请
- 核心主张：**保留 TeamSpeak 的低延迟、隐私与控制权，用 PowerfulTS 补上现代社区需要的开箱即用体验。**
- 视觉基调：沿用项目“深海蓝观测台”设计——近黑背景、品牌蓝信号线、冷白文字、少量绿色在线状态；不用泛滥霓虹和密集卡片。
- 音乐建议：前 20 秒使用压迫、碎片化的电子节拍；TeamSpeak 出场时瞬间抽空；PowerfulTS 出场后进入干净、有推进感的科技电子乐。

## 一句话故事线

当现代语音软件越来越像一个庞大的内容与消费生态，而 TeamSpeak 又停留在“语音核心强、现代体验要自己拼”的状态时，PowerfulTS 把监控、点播、社交、通知和游戏联动重新聚合到一个开源 Web 面板里。

## Remotion 制作落地说明

- 每个画面只保留一个主信息；1920×1080 成片中，关键文字距左右至少 140px、距上下至少 100px。
- 建议主标题 120–156px，功能短句 64–78px，署名 / 链接不低于 42px。
- 真实 UI 不要整页缩到无法阅读。用局部放大、光标操作与高亮框按时间依次展示功能。
- 场景以 `TransitionSeries` 编排。常规场景使用 8–12 帧 fade / wipe；只有“竞品噪声 → TeamSpeak 极简空间”和“TeamSpeak → PowerfulTS”使用强转场。
- 色差、扫描线、噪点仅用于第一幕的“信息负担”，PowerfulTS 登场后立刻切回锐利、稳定、低噪的画面语言。
- 所有动画由帧驱动；不用 CSS transition / animation。字幕按短语切分，不做逐字乱跳。
- 后续实现时，实际总帧数需要扣除转场重叠帧；以最终旁白音频时长重新校准每个 Sequence。

## 事实口径与使用边界

- 竞品段落比较的是产品取向与使用摩擦，不宣称 YY、KOOK、OOPZ 的基础语音必须付费，也不宣称 OOPZ 有广告。正式画面最好使用抽象信息牌，不直接复刻其 UI。
- KOOK 官方将 BUFF 定义为会员增值产品，其中包含高品质立体声、队友降噪、语音流畅度优化等权益；OOPZ 官方同时主张“无广告”，并提供“无限公民”会员与商城权益。因此脚本只说它们存在会员 / 商城生态，不说“所有语音能力都收费”。
- TeamSpeak 官方强调低延迟、隐私、安全、去中心化 / 自主托管。TS3 非商业自建原生许可为 1 个虚拟服务器、32 槽且无许可费用；超过该范围可能需要付费许可。成片使用“核心语音不靠会员解锁”，不使用“任何规模永远完全免费”。
- PowerfulTS 当前版本为 v0.11.0，README 明确标注为早期开发与测试阶段。宣传片必须保留早期版本提示。
- PowerfulTS 自身不包含 TeamSpeak 服务端和 TSMusicBot；音乐与点播能力依赖自行部署的 TSMusicBot。QQ 提醒依赖可选的 NapCat / OneBot 配置。
- 展示在线音乐、B 站视频和背景音乐时，只使用具备合法宣传用途的素材；不要把音乐平台会员内容本身打包进宣传片。

## 审片时建议优先确认

1. 是否接受约 140 秒的完整叙事长度，还是需要另剪 60 秒版。
2. 竞品段落的力度是否合适；当前版本偏克制、可公开发布。
3. 是否要在正式成片中加入作者 / 社区名称、QQ群或演示站地址。
4. 是否能提供一套填充了真实但可公开数据的 PowerfulTS 演示环境，用于录制 Dashboard、音乐、好友、Steam 与管理后台。
